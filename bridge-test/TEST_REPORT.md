Добавлены семь проверок SQLite и три сценария HTTP/Chromium; расширена проверка
UI клубов. Подтверждены:
- привязка к полной почте из подтверждённого профиля Moodle, отдельно шесть цифр номера;
- отсутствие доступа к профилю до входа, изоляция аккаунтов и разных доменов с одинаковым номером;
- сохранение имени, фамилии, курсов, оценок, дедлайнов, текста/таблиц открытых материалов;
- сохранение выбранных клубов после повторного входа и переоткрытия SQLite;
- граница обновления ровно в 00:00 Астаны, а не через 24 часа после записи;
- обновление активных пользователей, обновление отсутствующего пользователя после следующего входа;

База по умолчанию: bridge-test/data/bridge.sqlite3, права файла 0600, WAL.
Тесты используют временные базы, не пользовательский файл.
Клубный справочник импортируется ежедневно из community.json: дата checked
не подменяется датой импорта и не означает ежедневную проверку внешних контактов.
Материалы сохраняются по мере открытия (до 30 документов на аккаунт), вложения не скачиваются.

## Сохранённый вход и истечение LMS — 22 октября 2026

По прямому запросу пользователя вход теперь сохраняется на 30 дней. Cookies,
localStorage и IndexedDB Microsoft/Moodle шифруются Fernet; ключ хранится отдельно
от SQLite с правами 0600. Сырой токен приложения не хранится: только SHA-256.
Пароль не сохраняется. Старый общий session.json не используется.

Полный прогон: **60 unittest прошли, 7 пропущены**, UI и smoke прошли.
[Журнал](session-test-run.log). Дополнительная регрессия выхода:
[тест одновременного сохранения и выхода](session-logout-race.log).

Новые проверки:
- четыре независимых аккаунта сохраняют cookies Microsoft/Moodle, localStorage
  и IndexedDB; после закрытия contexts, очистки RAM-сессий, пересоздания BrowserPool
  и переоткрытия SQLite восстанавливают кабинет без нового запроса пароля;
- полное истечение LMS с ещё действующим Microsoft SSO: новый OIDC-вход,
  в том числе экран Stay signed in, возвращает свежие данные того же пользователя;
- Microsoft требует MFA: возвращается кэш с исходной датой, кабинет остаётся
  открытым даже после перезагрузки страницы, повторных автоматических запросов нет;
- другой аккаунт в ответе SSO не принимается за владельца сохранённой сессии;
- keepalive не меняет активное окно; logout отзывает сохранённый токен даже
  при параллельной записи cookies; остальные пользователи продолжают работать;
- повреждённое/подменённое состояние, чужой токен, истёкшая запись и потерянный
  ключ не дают восстановить чужие cookies;
- Stay signed in выбирает Yes ровно один раз.

Все Microsoft/Moodle-ответы в этих сценариях — контролируемые страницы.
Проверена перезагрузка всех объектов состояния приложения, а не живой вход
в университетский аккаунт. Реальный Microsoft может потребовать MFA при отзыве
сессии, смене политики или проверке риска: его требование не обходится.
