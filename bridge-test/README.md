# Мой AITU — многопользовательский bridge

Рабочий проект: `endterm/bridge-test`. Требования и ограничения: [REQUIREMENTS.md](REQUIREMENTS.md).

## Запуск

Из `AITU/endterm`:

```bash
venv/bin/python -m pip install -r bridge-test/requirements.txt
venv/bin/python -m playwright install chromium --only-shell
BRIDGE_HEADLESS=1 venv/bin/python bridge-test/app.py
```

Адрес: `http://127.0.0.1:1740`; с другого устройства — адрес сервера, порт 1740.
Для реальных учётных данных во внешней сети настрой HTTPS.
[Пример Nginx](deployment/nginx.conf.example) требует своего домена и сертификата;
он автоматически не применяется. Размещение в Казахстане отдельно не проверено.

| Настройка | По умолчанию |
|---|---|
| BRIDGE_HOST | 0.0.0.0 |
| BRIDGE_PORT | 1740 |
| BRIDGE_HEADLESS | 1; значение 0 явно открывает окно на сервере |
| BRIDGE_MAX_SESSIONS | 12, минимум 3 |
| BRIDGE_DB_PATH | bridge-test/data/bridge.sqlite3; путь к SQLite-кэшу |
| BRIDGE_AI_MODEL | qwen3-vl:4b, установленная на текущей машине |

Запускай **один процесс Uvicorn**: активными браузерами управляет этот процесс; сохранённые входы находятся в SQLite.
Для нескольких workers понадобятся маршрутизация к владельцу сессии и общее управление браузерами.
Лимит 12 ограничивает ресурсы. Нагрузка проверена для трёх пользователей; восстановление и изоляция входа — для четырёх.

## Сессии

Отдельная случайная HttpOnly/SameSite=Strict cookie связывает посетителя с его непостоянным
Chromium BrowserContext, страницами, MFA, блокировками, кэшем и уведомлениями.
При HTTPS cookie имеет Secure. Chromium общий, contexts изолированы.
Разные профили/устройства независимы; вкладки одного браузерного профиля используют один аккаунт.

После первого подтверждённого входа кабинет запоминается на **30 дней**.
Перезагрузка страницы, закрытие браузера и перезапуск сервера не требуют ввода
пароля, пока сохранённая сессия принимается Microsoft. В SQLite сохраняются только
SHA-256 случайного токена приложения и зашифрованное состояние конкретного браузера:
cookies, localStorage и IndexedDB доверенных Microsoft/Moodle origins.
Шифрование — Fernet; отдельный ключ рядом с БД (bridge.key), права 0600.
Почта и шестизначный номер сами по себе не дают доступа: нужен секретный HttpOnly token.
Привязка зашифрованного состояния к токену и Moodle ID проверяется при восстановлении.
На экране Microsoft «Stay signed in?» приложение выбирает Yes.

При открытом кабинете подключение к Moodle поддерживается чтением своей страницы
примерно каждые четыре минуты. После истечения LMS приложение пробует новый OIDC-вход
через существующую сессию Microsoft, без ввода/хранения пароля. Автоматически
подтверждается только собственный Moodle ID. Если нужен новый MFA, кабинет остаётся
в режиме сохранённых данных и показывает кнопку восстановления. Автоматических
повторных MFA-запросов в цикле нет. Политику истечения/отзыва сессий Microsoft это не отменяет.

«Выйти» закрывает только текущий context и отзывает его сохранённый вход в БД,
в том числе при одновременном сохранении cookies. Учебный кэш аккаунта остаётся.
После 30 минут отсутствия запросов активный context освобождается; сохранённый вход
остаётся доступен для восстановления. Неподтверждённые подключения живут до восьми часов.
При заполнении лимита новые подключения получают 503/Retry-After.

Пароль очищается после MFA, ошибки, отмены или успеха. Ответы валидации не раскрывают входные
пароли. Вход ограничен пятью попытками за десять минут в одной сессии.
На публичном прокси нужны дополнительные лимиты: создание новой cookie обходит сессионный лимит.
Межсайтовые команды отклоняются, ответы имеют no-store, CSP, no-referrer и защиту от встраивания.
Обязательные MFA и политики Microsoft не обходятся.

**Старый общий файл `~/.local/state/aitu-bridge/session.json` не читается и не создаётся.**
Ранее созданный пользовательский файл автоматически не удаляется.
`session_store.py` оставлен как прежняя неиспользуемая утилита; приложение его не импортирует.
По новому запросу пользователя учебные данные сохраняются в SQLite: профиль,
курсы, дедлайны, оценки, текст/таблицы открытых материалов и клубы.
По последующему запросу пользователя cookies и браузерное состояние теперь сохраняются зашифрованными.
Пароли и история чата не сохраняются.
Файл базы имеет права 0600, каталог данных исключён из Git.

## Функции

- Прежние курсы, материалы, оценки и Timeline из текущего Moodle-аккаунта.
- Календарь дедлайнов из Timeline, текущий месяц, переход по месяцам и события дня,
  время Астаны. Отдельный официальный календарь экзаменов ещё не подключён.
- Уведомления о загруженных сроках, счётчик и «Прочитать все». Отметки сохраняются
  при перезагрузке страницы до выхода/истечения сессии. Наличие дедлайна не означает,
  что работа не сдана. Push-уведомлений нет.
- [Карта кампуса](https://yuujiso.github.io/aitumap/) встроена с указанного пользователем адреса;
  есть открытие в отдельной вкладке. Занятость аудиторий не показывается.
- Поиск клубов по названию и категории. Названия/контакты взяты из
  [официального списка AITU](https://astanait.edu.kz/ru/student-clubs), проверенного 22.10.2026.
  Категории сгруппированы для удобства; отсутствующие контакты обозначены явно.
  Доступность всех Instagram/Telegram-ссылок отдельно не проверялась.
  Публичный справочник `community.json` не содержит персональных данных студентов.
- Быстрая верхняя навигация, мобильный и широкий экран.
- Постоянный SQLite-кэш до 30 документов на аккаунт, дополнительно краткий кэш в памяти.
  «Обновить» принудительно читает источник. Максимум 500 уведомлений на сессию.
- «Мои клубы»: личные отметки и фильтр сохраняются между входами; это не запись в клуб.
  Медленный запрос одного посетителя не удерживает блокировки других.

AITUSA, дополнительная интеграция MyDU/Learn и занятость аудиторий отложены по указанию пользователя.
Отправка работ и прохождение Learn-квизов не реализованы.
Первое чтение внешнего сайта может занять больше трёх секунд.

## База данных и ежедневное обновление

SQLite включена автоматически, отдельный сервер БД не нужен. Используются WAL,
короткие транзакции и выполнение запросов вне основного event loop.
Схема создаётся/обновляется автоматически: students, documents, selected_clubs, catalog, remembered_sessions.
При переносе работающего сервера делай согласованную SQLite backup-копию, а не
копию одного файла без его WAL. Для обычного переноса останови сервер и перенеси каталог data,
включая ключ bridge.key. Без ключа учебный кэш доступен, но восстановить cookies нельзя.

Ключ — нормализованная полная почта из собственного профиля Moodle, привязанная
к Moodle user ID. Первые шесть цифр сохраняются отдельно как student_number;
одинаковые номера в разных доменах не объединяются. Введённой в форме почты
недостаточно для доступа к сохранённым данным: нужен успешный вход Microsoft/Moodle.
Имя/фамилия читаются из полей собственного профиля; при отсутствии отдельных полей
сохраняется отображаемое имя, без угадывания порядка слов.

После первого чтения фоновая задача загружает курсы, Timeline и оценки.
Открытые материалы также сохраняются, до 30 документов на аккаунт. Приложение
не обходит рекурсивно все ссылки и не скачивает вложения: сохраняет данные,
которые умеет читать текущий интерфейс. Фоновое чтение использует временные вкладки.

Обновление начинается ежедневно в **00:00 по Астане (Asia/Almaty)**.
Это граница календарного дня, не 24 часа с момента записи. Обновляются профиль,
основные разделы и сохранённые материалы пользователей с действующей Moodle-сессией,
до трёх аккаунтов одновременно. Личные отметки клубов обновление не сбрасывает.
Для неактивного пользователя обновление произойдёт при следующем открытии кабинета.
Если Microsoft потребовал MFA, свежие данные появятся после подтверждения входа. При выключенном сервере задача в полночь не выполняется; устаревание всё
равно проверяется при обращении. Для повторного входа используются зашифрованные cookies;
пароли не хранятся. Если Microsoft требует MFA, обновление ждёт подтверждения пользователя.

При сетевом сбое старая копия остаётся с прежней датой и явным предупреждением.
Кнопка «Обновить» позволяет не ждать полуночи. API /api/profile выдаёт только
профиль владельца сессии, /api/profile/clubs меняет только его отметки.

Общий справочник клубов также кэшируется на день из community.json.
Поле checked обозначает дату исходной проверки контактов; ежедневное чтение файла
не означает повторную проверку внешних сайтов или наличие данных о членстве в клубах.

## Локальный AI

Ollama вызывается только на `127.0.0.1:11434`, без сетевого прокси и внешних API.
На другой машине потребуется установленный Ollama и модель, выбранная через BRIDGE_AI_MODEL.
При недоступной модели UI показывает 503 с понятным объяснением.

Передаются вопрос, названия курсов и дедлайны из загруженных страниц только текущей сессии.
Профиль, оценки, cookies, пароль и полные страницы не передаются. История чата не сохраняется.
Ответ — обычный текст; инструментов и прав на изменение LMS у модели нет.
Допускаются три генерации одновременно, по одной на сессию.
До открытия курсов/Timeline учебный контекст пуст. Сведения могут быть устаревшими;
проверяй ответы модели по Moodle.

[ai-test-results.json](ai-test-results.json) содержит живые ответы на пять синтетических вопросов
и измеренное время. Повторить: `venv/bin/python bridge-test/test_ai_live.py`.
Генерация может быть медленнее трёх секунд; при трёх реальных параллельных запросах
максимум составил 16,67 с, основные API-запросы продолжали отвечать.
[Результат параллельного AI-теста](parallel-ai-results.json).

## Тесты

Из `AITU/endterm`:

```bash
BRIDGE_HEADLESS=1 venv/bin/python bridge-test/run_tests.py
```

Проверяются запуск Chromium; 32 сценария Microsoft/MFA; парсер;
cookies и память сессий; UI на 320/390/430/1440 px;
три одновременных входа и 300 запросов нагрузки через настоящий HTTP/Chromium;
чужие окна, выход, истечение, лимиты, уведомления и изоляция AI-контекста;
локальный smoke со вспомогательным браузерным экраном.

Microsoft/Moodle в тестах заменены контролируемыми страницами.
Семь прежних проверок явно пропускаются (SKIP), если отсутствует `AITU/mid-term/materials`.
Живую публичную страницу входа можно отдельно проверить:
`BRIDGE_LIVE_SMOKE=1 BRIDGE_HEADLESS=1 venv/bin/python bridge-test/smoke_test.py`.
Реальные пароли в автоматических тестах не используются.

## Посещаемость

Пункт «Посещаемость» сразу открывает общий календарь: сервер сам находит доступные
журналы Attendance во всех загруженных курсах. Выбор курса и журнала для просмотра
не требуется. Фильтр курса, переключение месяцев и нажатие на день работают локально,
без дополнительных запросов к LMS.

В календаре показаны цветные отметки; ниже — занятия, исходный статус, баллы и
комментарий преподавателя. Счётчики относятся к выбранному месяцу и курсу.
Неизвестные статусы не трактуются как пропуски, записи без полной даты не скрываются:
они находятся в блоке «Другие записи». Итоговые проценты и исходные таблицы доступны
в раскрывающемся блоке LMS; приложение не пересчитывает официальный процент.

POST /api/attendance принимает только refresh: bool. Сбор ограничен 90 секундами,
обращения одного пользователя выполняются последовательно в его изолированном контексте.
При частичной ошибке остаются загруженные записи и предупреждение; при недоступности
LMS читается личный кэш. Смена аккаунта в ходе сбора отменяет ответ.
Открытые документы обновляются ежедневно в 00:00 по Астане; кнопка обновления
сразу запрашивает данные из LMS.

Используется личный отчёт стандартного Moodle mod_attendance за весь период (view=5).
Чужие studentid и параметры действий из ссылок отбрасываются; сервер подставляет ID
текущего пользователя. Отметки не выставляются и не изменяются.
Совместимость сверена с [исходным кодом Attendance](https://github.com/danmarsden/moodle-mod_attendance/blob/MOODLE_503_STABLE/view.php).
Автотесты используют синтетические страницы; живая разметка журнала AITU в этой проверке
не использовалась.

Интерфейс использует локальные SVG Flaticon Uicons Regular Rounded. Происхождение
и преобразование исходных контуров описаны в [FLATICON.md](FLATICON.md);
[лицензия](FLATICON-LICENSE.txt) сохранена, ссылка на автора отображается в приложении.
